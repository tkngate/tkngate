# Enterprise Virtual Keys

Tkngate allows you to move away from trusting client-provided headers and utilize a true Enterprise Authentication model with Virtual Keys.

## What are Virtual Keys?

Virtual Keys are secure tokens (e.g. `tkngate-sk-...`) generated by the Tkngate proxy. You issue these keys to your developers or external teams instead of your physical OpenAI, Anthropic, or DeepSeek keys.

When a client makes a request using a Virtual Key, Tkngate handles the request, enforces budget caps, and then abstracts the underlying physical key through the DRR Mesh.

## Managing Virtual Keys

You can use the `tkngate auth` CLI commands to manage Virtual Keys:

### 1. Generate a Key

To create a new virtual key with a specific budget and name:
```bash
tkngate auth generate --name "marketing-team" --budget 150.00
```
This command outputs the raw `tkngate-sk-...` string. Ensure you save this securely, as it won't be shown again.

### 2. List Active Keys

To view all active Virtual Keys, their allocated limits, and consumed budget:
```bash
tkngate auth list
```

### 3. Revoke a Key

To instantly invalidate and delete a virtual key:
```bash
tkngate auth revoke --name "marketing-team"
```

## Budget Isolation

Each Virtual Key acts as an isolated sandbox. It tracks its own spend (`consumed_budget_usd`) against its allocated limit (`allocated_budget_usd`). If a Virtual Key hits its allocated budget limit, Tkngate automatically cuts off access for that specific key with a `402 Payment Required` or `429 Too Many Requests`, protecting your global physical API limits.
